# 当時の提出書類索引の追加収集

2026年9月10日。3年土台の収集中に、同時に必要になる2022〜2024年の全四半期の公式提出索引12本を揃える。

各年の開始時点より前の提出記録だけを読み、年初の証券候補200件を提出会社名と照合する。これは当時の原書類を探すための候補提示で、名前の一致を同一証券や低保有認定へ読み替えない。既存の会社名照合処理を使い、過去の書類名表記や証券番号・銘柄コードの照合は次工程で確認する。

初回のGitHub Actionsでは市場取得が成功し、SECの取得は403だった。同じ公開URLはローカルの通常のHTTP取得で応答したため、SECの収集はそこで続行する。認証の偽装や公開対象の変更は行わない。実行環境の違いと各入力のハッシュを結果に記録する。

追加：報告上の普通株表記だけでは対象範囲が広いため、前年第3四半期の公式証券一覧PDFを取得してCOM／COM SHS（削除除外）と照合する。全行数を一覧の総件数と照合し、重複証券番号の分類矛盾は停止する。狭い表記抽出で全普通株を網羅するものではない。損益は計算せず、照合後の集合から同じ固定ハッシュ順で200件を作り直す。

再実行は `python -m research.history.collect --scope public` → `python -m research.history.security_lists` → `python -m research.history.indexes`。公式PDFの読み取りには `pdftotext`（Poppler）が必要。元ファイルがあればURLとハッシュを照合して再利用する。市場収集はGitHub Actionsの手動実行でmarketを選ぶ。

保存方法の追加：90日で期限を迎えるActions添付に加え、取得済み暗号ファイルと派生候補・品質台帳を保存用ZIPにまとめて別途保管する。原計画と初回失敗ログは保持する。
