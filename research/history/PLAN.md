# 2023〜2025年のデータ土台（2026年9月10日）

条件調整より先に、取得範囲・資料の時点・保存方法を固定する。今回、通知と損益は計算しない。2023〜2024年を開発用、2025年を条件確定後の比較用とし、既に閲覧した2026年は参考記録のままにする。2026年を見て着想した研究であり、過去年を真に前向きな未知の試験と呼ばない。

## 今回取得するもの

- 各年1月1日より前に提出された前年9月末の保有報告を復元する。対象アーカイブは2022年・2023年の第3／第4四半期、2024年9〜11月と2024年12月〜2025年2月。後者の年明け提出は選定へ使わない。
- 報告上の普通株表記から証券候補の全一覧と、銘柄コードや将来利益を使わない固定順の200件を各年で保存する。現在上場している銘柄一覧で絞らない。機関保有が全く報告されない証券はこの一覧には入らず、全米上場普通株の完全な名簿とは呼ばない。
- この段階では銘柄コード、普通株・会社種別、上場状況、発行済み株数、低保有割合の適格認定は未完了。現在の54銘柄を昔の検証対象として採用しない。
- 市場データの取得・保存の実測として、既存54銘柄とユーザー指定の試験5銘柄および比較用SPYを取得する。これは収集技術の試験であり、各年の正式な検証対象ではない。当時の証券候補とコードを照合した後、そのコードの不足分を追加する。
- 日足の開始・高値・安値・終了価格・出来高を、補正なし／分割補正／分割と配当補正の3種類で保存。2022年9月〜2026年1月を収集し、過去60営業日の基準と2025年末通知の追跡期間を確保する。最新の補正値を当時の判定へ自動投入しない。

## 品質と保留

ページの取り残し、日付の重複・順序、営業日との一致、価格の大小関係、ゼロ出来高、補正方式間の日付差を記録する。取得できない期間は不明のまま残す。新規上場前、コード変更、上場廃止、提供元の欠落を後で資料に照合し、欠けを0で埋めない。補正方式間の差は分割や配当の候補にすぎず、企業行動の正式な証明とは呼ばない。

## 保存

取得時刻、取得条件、コード版、資料URL、SHA-256を保存。既存ファイルとハッシュが合わない場合は黙って再利用しない。通信は回数・時間・容量を制限し、失敗を原因分類して記録する。

市場の原数値は秘密鍵から用途別に導いた暗号鍵で暗号化する。暗号化には既存の標準ライブラリ cryptography の Fernet と HKDF を使い、復号とハッシュ一致までその場で確認する。APIキーそのものは保存しない。復号には収集時の `ALPACA_SECRET_KEY` が必要なので、キー更新時は旧データの再暗号化が必要。公的な証券候補一覧は平文で保存する。

GitHub Actionsの実行添付として90日間保持する。これは無期限の保管ではない。添付の識別番号と期限を台帳に記録し、後続作業で利用・移管する。SECの大きな原圧縮ファイルは取得URLとハッシュを記録し、今回の添付は派生候補一覧と市場データの暗号ファイルを中心にする。

## 完了の区別

今回の取得が成功しても「3年バックテスト完成」ではない。年初の候補一覧と原データ保存を第一の完了点とし、次に当時の証券とコード・上場・株数の対応を解決する。最終的に、正式対象の価格が揃い、欠損理由と企業行動が扱えるようになってから条件の検証へ進む。
