# 第2段階：保有資料の集計と株数の照合

2026年9月10日／コード0.3.0／保有資料の点検仕様 holdings-audit-0.1

**SEC公式の一括ファイル2本、計7,296,094行を読み取り、2025年12月末・2026年3月末の指定5銘柄を全提出者から抽出した。訂正の反映、共同報告の関係の記録、発行済み株数との対応まで実装した。機関保有率の認定と、モデルのバックテストはまだ行っていない。**

今回の成果は、一社の保有を見る試験から、収録された全提出者を対象に集計・点検する処理へ進めたこと。取得した範囲での欠落や重複の疑いを残し、後から修正できる記録を作った。

[集計結果・入力のハッシュ・問題の代表例](evidence/sec-bulk-holdings-2026-09-10.json)

## 取得した資料と、再現する時点

| 一括ファイルの収録範囲 | 提出書類数 | 保有明細の行数 | ZIPの容量 |
| --- | ---: | ---: | ---: |
| 2025年12月1日〜2026年2月28日に提出 | 11,372 | 3,473,209 | 90,264,650バイト |
| 2026年3月1日〜5月31日に提出 | 11,761 | 3,822,885 | 99,411,274バイト |
| 合計 | 23,133 | 7,296,094 | 約190MB |

この期間は**書類を提出した日**の区分。保有の基準日とは異なり、過去の四半期を訂正する書類も混ざる。例えば、12月末の保有を5月に訂正した書類も処理対象にする。[SEC公式一括データ](https://www.sec.gov/data-research/sec-markets-data/form-13f-data-sets)

今回調べた公開一覧では、2026年5月末までの一括ファイルが最新だった。分析の情報時点を**2026年6月1日**とし、その日より前に提出された情報だけを使った。9月現在の保有率の推計には流用しない。

一括ファイルを9月に取得していても、対象選びに使えるのは個別の書類が公表されてから。一括ファイルの収録期限・取得日・保有基準日・個別の提出日を分けて保存する。このファイルには提出時刻がないため、同日提出分は使わない。市場の営業日・通知の受信時刻との接続は、本格検証時の追加作業。

今回の集計には、12月末について10,753提出者、3月末について10,648提出者の書類が含まれた。これは収録された報告者の数で、世界の全機関の数ではない。未提出、遅延、秘密扱い、小口の省略、報告対象外などが残る。

## まず数字を計算し、不確かさを分けた

下表は2026年3月末の資料について、訂正を反映し、株式種類や行数の検査を通った行を合計した結果。**共同報告の重複をまだ完全には整理できていないため、全機関の保有率を表す数字ではない。**

| 銘柄 | 集計に入った報告者数 | 点検用の合算株数 | 対応した発行済み株数 | 点検用の仮比率 |
| --- | ---: | ---: | ---: | ---: |
| UAVS | 43 | 4,677,116 | 57,346,783（3月31日） | 8.16% |
| QMCO | 36 | 1,593,540 | 14,638,029（2月12日） | 10.89% |
| MU | 2,888 | 840,701,102 | 1,127,734,051（3月11日） | 74.55% |
| ONTO | 556 | 47,251,084 | 49,744,000（3月31日） | 94.99% |
| AAOI | 361 | 52,893,491 | 78,971,000（3月31日） | 66.98% |

計算は「資料から合算した株数 ÷ 発行済み株数 × 100」。同じ株を二度数えると高くなり、報告や行を取りこぼすと低くなる。両方の問題があり得るため、この仮比率は真の保有率の上限・下限としても使わない。

UAVS・QMCOには低保有の対象候補を調べる材料が得られたが、低保有と認定するフラグは全5銘柄で未確定のまま。今回の5銘柄だけで「下位3分の1」を決めることもしない。

前期の点検用合算はUAVSが3,278,501株、QMCOが2,055,009株だった。しかし、両期の共同報告と未解決の書類がまだ揃っていないため、これをそのまま機関の純買い・純売りの正解データにはしない。

## 実データで見つけた問題と、今回の処理

### 1. 元報告と訂正を足すと、保有が膨らむ

Vanguard Capital ManagementのUAVSは、元の報告にも、全表を置き換える訂正版にも1,820,175株が載っていた。両方を足すと3,640,350株になる。今回は訂正版へ置き換え、この重複を解消した。

同じ会社が同日に追加報告も提出していたため、単に「最後の書類だけを選ぶ」方法も使えない。

| 書類の種類 | 処理 |
| --- | --- |
| 当初報告 | その提出者・その四半期の出発点 |
| RESTATEMENT（全表の訂正） | それまでの表を置き換える |
| NEW HOLDINGS（追加報告） | 現行表へ追加する |
| NOTICE（他の提出者が報告する旨の通知） | 参照関係を保存。保有株数を再加算しない |
| 訂正順が曖昧、追加なのに元表がない、途中の追加が欠ける | その提出者を未解決として記録 |

全訂正が完全な表を再提出している場合は、古い不備を引き継がず、その訂正から再開できる。[SECの13F FAQ・訂正の説明](https://www.sec.gov/rules-regulations/staff-guidance/division-investment-management-frequently-asked-questions/frequently-asked-questions-about-form-13f)

### 2. 関係会社の報告は、同じ株を数えている可能性がある

Calamos AdvisorsとCalamos Wealth Managementの3月末報告には、UAVSがそれぞれ301,672株載っていた。前者の表紙には、後者との報告上の関係も記載されている。

これは重複を疑う具体的な例。ただし、株数が同じだけでは同一保有と断定できないため、今回は勝手に片方を削除せず、両者の提出番号と株数を未解決の組として残した。

一方、Geodeのように同じ書類内で共同運用分とそれ以外が別行になっている場合、両方を合算する必要がある。共同運用を表す記号がある行を全部捨てる処理はしていない。[13F公式記入要領](https://www.sec.gov/files/form13f.pdf)

表紙で「他者が報告する」とされる相手と、情報表で「自分の報告に含める」とされる相手も区別した。提出者番号がない場合は、書類管理番号を照合する。名前だけで関係会社を同一視しない。

### 3. 分母を新しい数字に差し替えると、過去の判断が変わる

UAVSの四半期報告で、12月末43,613,800株、3月末57,346,783株という普通株の発行済み株数を確認した。優先株や「発行できる上限」と区別した。[UAVSの2026年3月期報告](https://www.sec.gov/Archives/edgar/data/8504/000143774926017229/uavs20260331_10q.htm)

QMCOでは次の三つが別の数字になる。

| 数字の基準日 | 発行済み普通株数 | 公表日 | 今回の扱い |
| --- | ---: | --- | --- |
| 2025年12月31日 | 14,135,000 | 2026年2月17日 | 前期末の分母。書類の「千株」を株へ換算 |
| 2026年2月12日 | 14,638,029 | 2026年2月17日 | 3月末に対応する古い分母の参考値。47日のずれを表示 |
| 2026年3月31日 | 14,638,000 | 2026年6月25日 | 6月1日には未公表なので、その時点の入力から除外 |

さらに6月25日の書類の表紙には、6月24日時点の39,374,500株が載っている。これを3月末の分母へ差し替えると、過去の保有率が大きく変わってしまう。[QMCOの12月期報告](https://www.sec.gov/Archives/edgar/data/709283/000162828026008558/qtm-20251231.htm)、[3月期の年次報告](https://www.sec.gov/Archives/edgar/data/709283/000162828026045602/qtm-20260331.htm)

今回、UAVS・QMCOの採用した分母は原書類で普通株との対応を確認した。MU・ONTO・AAOIは公式の電子データから候補を選んだ段階で、同じ確認は残作業。同じ基準日の別の値が過去の書類にあれば、候補を消さずに記録する。

### 4. 収録された数字にも自己矛盾がある

3月末のQMCOでは、Flagship Harbor Advisorsの表紙が示す明細数722に対し、一括データの明細は732行だった。QMCOの17,185株の行は見つかったが、今回はこの提出者を合算から保留した。通信の欠落なのか、提出書類の記載ミスなのかを原表で切り分ける必要がある。

ほかにも、株式種類の欄がオプションを示すのにオプション欄が空の行などがあり、単純に「株数欄がある行」を全部足さないようにした。UAVSの表記揺れ1種類は、同じ証券番号と公式リストの普通株表記を確認して追加した。

不一致の提出者を除いても、残りが完全な所有者一覧になったとは扱わない。合算から外した書類、種類、照合できない参照を別に記録し、「見つからない」をゼロに変換しない。

## 実装・動作確認と再実行

- `flow_probe/bulk13f.py`：大きな明細表の逐次読み込み、行数照合、提出者・四半期別の訂正処理。
- `flow_probe/holdings.py`：公式証券リストとの対応、共同報告の関係、株数の候補、公表日の制限、要約と監査記録の出力。
- `flow_probe/holdings_reference.py`：原書類で確認した分母と証拠。日付・提出番号・値が変わったら確認済み判定を引き継がない。
- `tests/test_holdings.py`：追加19件。既存分を含む44件が成功した。これはコードの動作確認で、投資成績の検証ではない。

本物の二期のZIP、二期の公式証券一覧、5社の発行済み株数で処理を実行した。証券番号の先頭の0を落とさず、すべての明細を読み切っている。[2025年末の公式証券一覧](https://www.sec.gov/files/investment/13flist2025q4.txt)、[2026年3月末の公式証券一覧](https://www.sec.gov/files/investment/13flist2026q1.txt)

```bash
python -m flow_probe.holdings --fetch
python -m unittest discover -s tests
```

一括ZIPと証券一覧のハッシュを固定し、内容が変わった場合は点検待ちにする。会社の電子データは取得したJSONのハッシュと、採用した個別の数値・公表日を残す。本格バックテスト用の入力を永続保存して封印できた、という状態ではまだない。

通常の公開経路で今回の作業環境から取得できた。GitHubの実行環境で以前発生したSECへの403を、解決したとはみなしていない。一括取得は大きいため、市場側の接続試験が動くたびに約190MBを取得する構成にはしていない。

## 次の最小作業

1. UAVSのCalamos間の重複疑いと、QMCOの行数不一致を原報告で確認する。相手の提出者を確定できない共同報告も、影響する株数が大きいものから絞る。
2. その修正前後で二期の株数がどれだけ変わるかを示し、答え合わせに使える範囲を決める。判定不能は独立した状態として残す。
3. 当時公表済みだった対象群へ拡張し、低保有の分布と除外率を確認する。そのうえで最小モデルの判定と比較検証へ進む。

モデルの変数は増やしていない。出発点は引き続き「銘柄自身の過去に比べた出来高の異常」と「反復」の二つ。
