## 今回作ったデータ

`flow_probe/research.py` が市場データ取得後に次を行う。

- 各取引日に、当日より前の通常の長さの60営業日を対応させる。
- 過去の出来高を、その判定日の株数の単位へ揃える。将来の株式併合を、過去の判定入力に使わない。
- 短縮取引日、準備期間、欠けた日、重複、不正・ゼロの出来高、未解決の補正を理由別に保留する。
- 原数値を含む検証用ファイルを `data/stage2-daily.json` に作る。公開するのは件数、設定、内容のハッシュだけ。

GitHubの実行環境に作った原数値のファイルは、実行終了後には残らない。公開リポジトリへ市場データを置かず、同じ取得・準備を再実行する構成。提供元の過去データが訂正された場合はハッシュが変わる。本格検証では、非公開の永続保存先を用意し、取得時点の入力を固定してから最終試験に使う。

## 日足を採用する理由

最初の実装仕様を「通常時間の分足合計」から、**Alpacaが提供する全米市場の日足の出来高**へ変更する。今回、UAVS・QMCOでも分足のない区間に小口の約定が存在することを確認したため。

日足は通常取引時間だけの出来高とはみなさず、時間外も関係し得る提供元の日次集計として一貫して比較する。分足合計との混在、分足のゼロ埋め、短縮日の単純な時間比例補正は行わない。[Alpacaの集計規則](https://docs.alpaca.markets/us/docs/market-data-faq#how-are-bars-aggregated)

将来の通知は翌朝の取得を基準とする。引け直後に、あとから完成した日足をすでに知っていたことにしない。実際のデータ受信時刻を記録し、受信後の通常取引開始から価格を追う。

UAVSの最初の併合より前の出来高を、二度目の併合後の株数で表示する場合は1,000で割る。価格は逆に1,000倍になる。これを売買量の増減と取り違えない。

補正前後の終値から倍率を逆算する最初の診断では、小数価格の丸めによる差まで倍率の変更候補として拾った。この診断は記録に残し、正式資料の倍率で照合する処理へ修正した。価格の診断上の許容差は「補正前0.0001ドル×倍率＋補正後0.0001ドル」、出来高は1株。これは提供元の精度保証ではない。許容差内で一致した件数と、それを超える不一致を別々に記録する。

`flow_probe/reference.py` に資料URLと日付を保存する。これは今回の期間・銘柄の確認表であり、全銘柄の企業行動履歴ではない。追加の併合、増資、合併、証券番号の変更が見つかったら版を変えて再作成する。併合の補正だけで、増資による株数変化を解決したことにはならない。

## モデルを作る前に固定した出発点

| 項目 | 初期仕様 |
| --- | --- |
| 情報の種類 | 出来高の異常度と反復だけ。保有の少なさは対象選びに使う |
| 普段の基準 | 当日を含めない、直前60回の通常の長さの営業日 |
| 異常日 | 過去60日の出来高を小さい順に並べ、57番目の値を厳密に超える日。同値は異常にしない |
| 表示用の倍率 | 当日の出来高 ÷ 過去60日の中央値。異常度へ二重加点しない |
| 反復版 | 当日が異常で、直近5市場営業日のうち2日以上が異常 |
| 判定不足 | 直近5日のどれかが未判定なら反復も未判定。短縮日を通常日と同一視しない |
| 比較用モデル | 当日の異常だけ。反復による改善と発見の遅れを同時に測る |
| 総合点 | 作らない。95%境界は「機関が買った確率95%」ではない |
| 主な採点単位 | 銘柄×暦年四半期。同じ四半期の通知を独立した的中件数として水増ししない |
| 主な答え合わせ | その四半期の、補正した報告保有株数の増減。金額の増加や株価上昇で代用しない |
| 価格の副評価 | 受信後の次の通常取引開始を基準に10営業日。5・20日は補助。費用込み損益は別途固定後に計算 |

これらは最適値ではなく、今後比較される仮説。今回は異常日や収益を計算しておらず、成績を見て数値を選んではいない。

## 当時の情報だけを使う規則

対象選びには、その時点までに公表された保有資料と、対応する株式種類の発行済み株数だけを使う。基準日と公表日を分ける。公表時刻が不明なら翌営業日以降に利用可能とする。分母の基準日がずれている場合は古さを表示し、照合できなければ保有率は不明とする。

保有増減の答え合わせは、通知が属する四半期の前末から当末の変化と照合する。例えば2026年7月の通知を、3月末から6月末の増加で的中扱いしない。9月末の保有を報告する書類が揃うまでは採点待ちとする。提出訂正は当時版と答え合わせ版を区別する。

取得可能な3年のうち、試験の区分案は2024年を開発、2025年を比較、2026年1〜6月を最終確認とする。2023年の取得部分は準備用。**まだ最終試験として封印できた状態ではない。** 過去の銘柄群・保有報告の収録範囲と非公開保存を確認してから区分を正式確定し、採点を始める。比較期間の末尾で未公表だった答え合わせを、次の期間の開始時点の調整に使わない。

追記：過去時点の候補一覧と最初の確認対象200件を作成した。最新の対象選びの進捗は[時点を固定した候補一覧](STAGE2_COHORT.md)を参照。

## 残っている作業と次の判断材料

1. **保有の集計**：全提出者・訂正報告への拡張は実装・実測済み。残る共同報告の重複疑い、行数不一致、参照先の照合を解決する。該当行なし・未提出・照合不能をゼロ保有へ変換しない。
2. **取得経路**：公式一括ファイル約190MBを今回の作業環境で取得できた。GitHubからSECへの403と、定期取得の安定性は未解決。収録期限が5月末の一括データだけで現在の保有率を作らない。
3. **株数と銘柄履歴**：発行済み株数の基準日、増資・自社株買い、旧証券番号と旧コードを揃える。当時の上場廃止銘柄を含む対象群を復元する。
4. **低保有の対象群**：当時の報告保有比率が低い群を作り、100〜300銘柄を目安に分布・流動性・除外理由を報告する。今回の5銘柄へ成績を合わせる調整はしない。
5. **採否基準**：通知率を揃えた単純モデル・比較群との差、採点可能数、不明割合、発見の遅れ、推定の幅を事前に決める。最良の値だけを拾う総当たりをしない。

これらの未解決部分を残したまま「機関流入を検知できた」「低保有銘柄で優位性がある」とは判定しない。原報告で確認できた修正は反映し、確定できない重複は影響を表示した。次は未解決の参照関係と除外範囲を整理し、当時の出来高と対応させる試験用の表へ進む。
