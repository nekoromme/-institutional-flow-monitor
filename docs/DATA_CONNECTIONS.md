# 追加データをどうつなぐか

2026-11-07。無料・既存のキーでできる範囲を実装し、本人操作が必要な部分を分離。
共通コマンドは `python -m market_hub enrich`。定期収集にも組み込み。
依頼は `config/source-request.json`、生データは共通SQLite、公開診断は `source-status.json`。
APIキーをチャットへ送る必要はない。

## 1. FRED：普通の履歴なら追加操作なし

FRED公式CSVをキーなしで取得する経路を追加。
米2年・10年金利、長短金利差、ドルウォン・ドル円、広義ドル指数、失業率、非農業雇用者数、CPIを対象に約10年。
CSVの空欄・欠損記号はnullで保存し、前日の値やゼロで埋めない。
月次グラフが期間境界を広げる場合、原CSVを保存したうえで依頼期間だけ切り出す。

**これは現在公表されている改定後の履歴。発表当時の数値ではない。**
現在の状況整理や値動きの比較に使い、昔の判断時点の特徴量へ無条件に投入しない。
当時版が必要な場合だけ、次の無料APIキーを用意する。

1. [FRED公式のキー発行ページ](https://fred.stlouisfed.org/docs/api/api_key.html)から自分のアカウントで発行。
2. [このリポジトリのActions秘密設定](https://github.com/nekoromme/-institutional-flow-monitor/settings/secrets/actions)の「New repository secret」で `FRED_API_KEY` を登録。
3. `株価分析ハブ・検証とデータ更新` を手動実行、または次回の定期実行を待つ。

実装はキーの有無だけを確認し、登録済みなら当時版APIも接続試験する。
キーを登録しただけでは成功扱いにしない。認証・権限・応答の実測結果を出す。

公式説明：[CSVダウンロード](https://fred.stlouisfed.org/help/data/downloading/using-the-download-data-link)、[当時版を指定するAPI](https://fred.stlouisfed.org/docs/api/fred/series_observations.html)。

## 2. 韓国株：ハイニクスとサムスンの参考日足を取得

NAVERの公開チャート経由で `000660` と `005930` を各1,500本取得する。
KRW、ソウル時間、取得時刻、原データを保存。進行中の日足は除外する。
ゼロ始値・ゼロ出来高などを正常な売買と見なさず隔離する。

NAVER配信はKRX公式APIではない。正式営業日カレンダーと補正方法の裏取りが未完了なので、
共通のイベント勝率計算には自動投入しない。米国株の取引日一覧を流用しない。
ADRとの価格差には同時刻の為替・本国価格と正式な預託比率が別途必要。

KRXから直接取る場合は[公式利用手順](https://openapi.krx.co.kr/contents/OPP/INFO/OPPINFO003.jsp)に従い、
本人の会員登録→認証キーの申請と承認→使用するAPIごとの申請と承認が必要。
現段階でKRXキー登録を必須にはしない。価格取得はNAVERで開始できる。
**KRXキーがあれば投資家別売買・信用・空売り等が全部取れるとは約束しない。API提供範囲は別途確認が必要。**
NAVERの投資家動向ページは今回の実測で403。アクセス制限を回避していない。

## 3. オプション：既存Alpacaキーの権限を実測

追加購入は行わない。既存キーで以下を読み取り専用で試す。

- MU・VRT・SOXLの今後35日以内のチェーン。参照株価があれば行使価格の範囲も限定。
- `opra` と `indicative` を別々に明示指定し、成否と契約件数を記録。
- 時刻付きデータのある代表契約について直近約1週間の日足と短時間の過去約定を取得。
- 契約情報APIで現在の建玉・建玉の基準日・契約倍率も取得を試みる。過去建玉のバックフィルではない。
- 取得済みのチェーン・現在IV・Greeksを日々保存。ただし最初から過去へ遡れると見なさない。

`indicative` は加工された参考配信。実際のOPRA気配として使わない。
履歴bars/tradesのAPIにはfeed指定が文書化されていないため、配信の身元を勝手にOPRAと断言しない。
公式文書では過去オプションは2024年2月以降。それ以前の網羅履歴はこの接続で得られない。
履歴気配のAPI経路は公式仕様に見つからず、実測も404。自動照会から除外した。
**過去のIV・建玉全体の自動取得は未実装・未確認。現在のチェーンで過去の建玉を代用しない。**

指定契約の任意履歴は `config/source-request.json` の `option_history_requests` に
`contracts`（配列）、`start`、`end`、`kind`（bars/trades）を設定すればActionsで実行できる。
ローカルでの形式は次のとおり（分析担当向け）。

```bash
python -m market_hub option-history --contracts MU261120C00100000 --start 2026-11-02T00:00:00Z --end 2026-11-06T22:00:00Z --kind bars
```

上の契約はコマンド形式の例。実在・取引・権限を確認し、依頼された契約に置き換える。
[公式の履歴範囲・配信説明](https://docs.alpaca.markets/us/docs/historical-option-data)。

## 4. 個人売買：無料上位10銘柄の接続口を追加

Nasdaq Data Link `NDAQ/RTAT10` は無料枠の上位10銘柄の指標。
全銘柄の活動に占める比率 `activity` と、直近10取引日のネットフローから派生した `sentiment` を保存。
**当日の純買付額、全市場の買い越し、全個人の実測台帳としては使わない。**

1. [Nasdaq Data Link](https://data.nasdaq.com/)でアカウントを作成し、Account Settingsで自分のAPIキーを取得。
2. [Actions秘密設定](https://github.com/nekoromme/-institutional-flow-monitor/settings/secrets/actions)へ `NASDAQ_DATA_LINK_API_KEY` として登録。
3. 次回実行で接続し、成功・対象日・件数を確認。

公式更新は火〜土10:00 UTC（日本時間19:00）頃。現在の15:35定期実行では直前営業日分がまだない場合がある。
最新の収録日を表示し、必要なら19時以降に再実行する。35日間を毎回再取得するので後日公表分も補える。

キーなしの今回の直接照会は403。キーなしの制限を回避せず、未接続のまま明示する。
登録後も403なら権限と配信環境を切り分ける。キー登録だけで成功を保証しない。
[公式仕様](https://data.nasdaq.com/databases/RTAT/documentation)。

全銘柄の売買量・金額や日中フローが必要なら、UREFやVanda等の有料サービスと利用許諾が必要。
現在は契約・課金を行わない。既存の公開報道を使う日次調査は引き続き使える。
有料化を検討するなら、料金より先に対象銘柄・期間・ネット/グロス・時間帯・API利用権を確認する。
既存の13Fは四半期保有であり、日々の主体別売買の代わりではない。

## 診断と保管

各取得先の成否を独立記録。一つが失敗しても他の成功データを暗号化して保管する。
処理全体が終了したことと全取得先の成功を区別する。`source-status.json` の各項目を確認。
取得した価格・気配・フローのデータ本体は公開ログや平文成果物に出さない。
公開するのは件数・取得日時・出所・制約・固定エラー区分だけ。
保持は共通キャッシュと同じ90日。永続的な履歴保証ではない。

## 公開情報を優先する運用（2026-11-07更新）

ユーザーの手間を減らすため `retail_flow_mode=public_reports` に変更。
**Nasdaqへの登録・キー発行は現時点では不要。** 接続口は残すが、未登録を障害扱いにしない。

既存の「米株の個人投資家フロー」調査は、すでに新規ログイン・課金を行わず
Vanda公式発表、公開された証券会社の顧客データ、Reuters・WSJ・CNBC等の閲覧可能な報道を調べる設定。
対象取引日と公表日、日中途中と終日、個別株とETF、売買総額と純買い越しを区別する。
出所の分からないSNS数字、取得できない有料本文、機関・個人の身元を推測した数字は採用しない。
公開記事がない日は未確認として扱い、古い数字やゼロで埋めない。
これはChatGPTの検索・本文照合による調査で、GitHub Actionsが有料データを取得した意味ではない。
したがって市場全体・全銘柄の欠けのない日次パネルとしてバックテストに使うことはできない。

FREDキー登録の申告を受け、PAYEMSの2024-07-10時点の公表版を取得する設定を追加。
接続成功は実行結果で確認する。現在の改定値を当時版と見なすテストではない。
