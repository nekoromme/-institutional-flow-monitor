# 第2段階：原報告の確認と集計の修正

2026年9月10日／コード0.3.1／保有集計 holdings-audit-0.2

**原提出書類4件の保有明細7,975行を、一括データと全行照合した。件数の食い違いがある2件を根拠付きで集計へ戻し、UAVSの重複疑いについては、重複の有無で結果がどれだけ変わるかを計算した。**

分析の情報時点は前回と同じ2026年6月1日。比較するのは2025年12月末と2026年3月末で、現在の機関保有率ではない。

比較したのは、証券番号、発行会社、株式種類、株数、オプション区分、運用上の権限、他の運用者、金額、議決権の株数。同じ行が2回ある場合も、回数を保って照合した。

原報告と一括データは、同じ提出を元にした資料。今回確認できたのは「元の表を取りこぼさず取り込めたこと」であり、独立した証拠で実際の所有者や取引を確認した意味ではない。

### QMCO：保留した17,185株を集計へ戻した

Flagshipの原表にはQMCOが17,185株と記載され、一括データの株数・金額・議決権などと一致した。原表は732行で、全行の金額の合計も表紙の合計金額と一致した。表の中に完全に同一の行の重複もなかった。[原表](https://www.sec.gov/Archives/edgar/data/1691766/000169176626000004/flagshipharbor1q2026.inftbl.xml)、[表紙](https://www.sec.gov/Archives/edgar/data/1691766/000169176626000004/primary_doc.xml)

前回は、表紙と行数が違うという理由で提出者全体を保留していた。今回は原表全体を確認できたため、この書類の保有行を点検用の合算に戻した。

ただし、722という件数をこちらで732へ書き換えてはいない。**原表の確認済み判定と、表紙の件数の警告を両方残した。** この例外を、同じ会社の別の提出書類へ適用しない。

### 前期末：原報告自身に件数の訂正があった

National Bank of Canadaの12月末報告は、表紙に5,429とある一方、追加説明に正しくは5,428という訂正があった。原表と一括データは、いずれも5,428行で全行が一致し、金額の合計も一致した。[訂正注記のある表紙](https://www.sec.gov/Archives/edgar/data/926171/000092617126000005/primary_doc.xml)、[原表](https://www.sec.gov/Archives/edgar/data/926171/000092617126000005/13fdecember2025holdings.xml)

これを根拠に、この書類も集計へ戻した。UAVSの1株、QMCOの100株に加え、同じ表にあるMU・AAOIにも反映している。全5銘柄の修正量は保存した比較結果にある。

この表には、内容が完全に一致する行の重複も10行分あった。原表と一括データで同じ状態なので、取得時に増えた重複ではない。別口座の同じ数量の可能性も残るため、まとめて削除せず、既存の重複検査を継続する。今回確認したUAVS・QMCOの該当行はそれぞれ1行だった。

### UAVS：重複の疑いは強まったが、同一保有とは確定できない

Calamosの2社には、UAVSがそれぞれ301,672株載っていた。株数だけでなく、金額272,711ドル、運用上の権限、議決権の株数なども一致する。さらに両社の表を横断すると、今回照合した項目がすべて一致する明細は256行あった。[Calamos Advisorsの原表](https://www.sec.gov/Archives/edgar/data/1316507/000131650726000002/infotable.xml)、[Calamos Wealth Managementの原表](https://www.sec.gov/Archives/edgar/data/1455258/000145525826000002/infotable.xml)

一方、この資料だけでは口座単位の同一性を確認できない。一般に、同じ保有を共同で運用する場合は一社が報告する仕組みだが、今回の同じ数字が実際に同一保有なのか、報告の誤りなのか、別の保有なのかまでは確定できない。[13Fの公式記入要領](https://www.sec.gov/files/form13f.pdf)

今回は片方の301,672株を自動で引かず、次の二通りを併記した。すべての不確かさを解決したという扱いにもしていない。

## 集計がどう変わったか

次は、重複の疑いをまだ差し引いていない点検用合算。単位は株。

| 対象 | 修正前 | 修正後 | 今回戻した株数 |
| --- | ---: | ---: | ---: |
| UAVS・2025年末 | 3,278,501 | 3,278,502 | +1 |
| UAVS・2026年3月末 | 4,677,116 | 4,677,116 | 0 |
| QMCO・2025年末 | 2,055,009 | 2,055,109 | +100 |
| QMCO・2026年3月末 | 1,593,540 | 1,610,725 | +17,185 |

QMCOの二期の点検用合算の差は−444,384株。これは「同じ集計規則で見た報告株数の差」であり、機関全体がその株数を売ったと確定したものではない。公開範囲の変化や運用者の交代、整理しきれていない共同報告なども影響する。

UAVSについて、**Calamosの問題だけ**を変えると次のようになる。他の報告は同じ数字に固定する。

| Calamosの2行の扱い | 3月末の点検用合算 | 前期末からの差 |
| --- | ---: | ---: |
| 同じ保有として1回だけ数える | 4,375,444 | +1,096,942 |
| 別の保有として両方数える | 4,677,116 | +1,398,614 |

この一つの問題だけなら、どちらの扱いでも合算は増加する。ただし、これは統計的な信頼区間でも、全誤差の上限・下限でもない。UAVSの3月末には、相手を確定できない参照なども11件残っている。

## 保有株数の増加だけを見ると読み違える

UAVSの発行済み株数は、同じ二期の間に43,613,800株から57,346,783株へ、**約31.5%増加**していた。[発行済み普通株数の原資料](https://www.sec.gov/Archives/edgar/data/8504/000143774926017229/uavs20260331_10q.htm)

先ほどの点検用合算を、それぞれの期末の発行済み株数で割ると、前期末は約7.52%、3月末はCalamosの扱い次第で約7.63〜8.16%。差は約0.11〜0.64ポイントになる。

保有株数の合算では約33.5〜42.7%増えていても、会社全体の株数も増えているため、割合で見ると増加は小さい。この仮比率も全機関の確定保有率ではないが、株数の増加だけで注目度の上昇を判断する問題を示している。

今後の答え合わせには、保有株数の変化に加えて、発行済み株数の変化と、計算可能な場合の割合の変化を併記する。公開資料で確かめられない取引の理由や、取引所で買った株か新しく発行された株かは推測で埋めない。

**通知モデルの変数は増やしていない。** 引き続き、出来高の異常と反復の二つ。今回加えたのは、答え合わせの読み違いを防ぐ点検と表示。

## 修正を後から取り消せる構成

- 原表の件数や株数は保存したまま、今回確認した書類にだけ別の利用判定を付ける。
- 提出番号に加え、日付・株数・株式種類・共同報告の相手などを含む元データ全体の指紋を照合する。内容が変わったら、この例外は適用しない。
- 訂正版が出ても、旧版の確認済み判定を引き継がない。当時未公表だった提出は引き続き除外する。
- 原書類を取得し直して、全行照合を再実行できる。取得した内容が変わっていたら、自動で修正履歴を上書きしない。
- 修正前後の結果を別々の記録として残す。保有率や機関流入の認定欄は未確定のまま。

追加10件、既存分を含む54件の動作確認が成功した。数字を変更したときの例外の取り消し、別の四半期や訂正版への誤適用、未公表資料の混入、重複行の見落としを検査した。原報告4件の全行照合も、再実行して記録と一致した。

GitHub上でも同じコードの54件の動作確認と市場側の接続試験が成功した。[実行記録](https://github.com/nekoromme/-institutional-flow-monitor/actions/runs/34437337335)（コード変更 `255891b0a278adc9e45b94d98bba6a810bf5d604`）。原報告の全行照合は今回の作業環境で実行しており、このGitHubの試験に含めたものではない。

```bash
# 初回は前の手順で一括データを取得。
python -m flow_probe.holdings --fetch

# 原報告4件を取得し、一括データと全行照合する。
python -m flow_probe.filing_review --fetch

# 取得済みの入力だけで再計算する。
python -m flow_probe.holdings
python -m unittest discover -s tests
```

今回の原報告取得は4件、約4.59MB、再試行を含む14回の要求で完了した。APIキーは不要。GitHub実行環境からのSEC取得の安定性と、入力データの永続保存先は引き続き別の課題。

## 次に進める範囲

1. 確定できない共同報告の参照を、影響する保有株数の大きいものから照合する。解決できない範囲と除外理由を固定する。
2. 今回のような報告株数の差を、当時の出来高と対応させる試験用の表へ進める。正解が不明な行を「買いなし」に変換しない。
3. 当時公表済みだった低保有の対象群を広げ、単純な出来高異常と反復版を比較する。今回の2銘柄だけで性能や境界値を決めない。

バックテスト成績、正式な低保有の認定、機関の純買いを確認したという判定は、まだ出していない。
